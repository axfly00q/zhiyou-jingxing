# 赛题要求落实清单

本文用于初赛提交、答辩和演示视频准备，按赛题截图中的要求对照说明“智游景行”当前实现、验收证据与演示顺序。

## 1. 赛题目标对照

| 赛题要求 | 当前实现 | 主要位置 | 验收方式 |
|---|---|---|---|
| AI 数字人导游，具备语音、文本、表情等多模态交互 | 游客端支持文字输入、语音录制、TTS 播报、VRM 数字人表情/动作和口型同步 | `frontend-web/src/views/tourist/Chat.vue`、`frontend-web/src/components/VrmAvatar.vue`、`orchestrator/app/api/chat.py` | 打开游客端，输入问题或按住语音按钮提问，观察数字人回答、播报和动作 |
| 景区历史、文化、特色等知识问答 | Orchestrator 调 Dify RAG，本地知识库兜底，支持 citations | `orchestrator/app/services/dify_client.py`、`orchestrator/data/kb/tour_guide/` | 提问“灵山大佛什么时候建成”“九龙灌浴有什么看点”等 |
| 个性化推荐路线和讲解重点 | 偏好页采集兴趣、时长、亲子/无障碍/赶时间等条件，KG 规划路线并生成开场白 | `frontend-web/src/views/tourist/Preference.vue`、`orchestrator/app/api/route.py`、`orchestrator/app/services/kg_planner.py` | 选择不同偏好，生成不同游览路线 |
| 游客反馈分析，辅助管理方优化服务 | 对话异步情感分析，满意度评分，后台服务建议聚合 | `orchestrator/app/services/sentiment.py`、`orchestrator/app/services/scheduler.py`、`frontend-web/src/views/admin/Suggestions.vue` | 后台查看服务建议、情感趋势和满意度 |
| 管理后台知识库维护 | 支持知识文档上传、维护，并作为数字人问答知识基础 | `frontend-web/src/views/admin/Knowledge.vue`、`orchestrator/app/api/admin.py` | 后台上传或查看知识资料 |
| 数字人形象管理 | 支持 VRM 数字人模型、动作、声音等配置 | `frontend-web/src/views/admin/Avatars.vue`、`orchestrator/data/avatars_vrm/` | 后台切换/维护数字人形象 |
| 数据大屏概览 | 展示服务人次、热门问答、景点热度、满意度趋势等运营指标 | `frontend-web/src/views/dashboard/Dashboard.vue`、`orchestrator/app/api/analytics.py` | 访问 `/dashboard` 查看大屏 |

## 2. 非功能要求对照

| 非功能要求 | 当前落实 | 证据 |
|---|---|---|
| 至少 1 个多模态大模型/大模型 API 作为核心 AI 能力 | Dify RAG/LLM 作为知识问答核心，ASR/TTS 作为语音链路，前端 VRM 负责数字人表现 | `docs/总体设计.md`、`orchestrator/app/services/dify_client.py` |
| 构建本地景区知识库 | `orchestrator/data/kb/tour_guide/` 与 `orchestrator/data/kg/lingshan.json` 提供知识问答和路线规划基础 | `orchestrator/data/kb/tour_guide/lingshan.md`、`orchestrator/data/kg/lingshan.json` |
| 事实性回答准确率不低于 90% | 离线评测脚本覆盖情感规则、KG 路线、对话标签；最近报告整体 94.12% | `orchestrator/scripts/eval_accuracy.py`、`docs/eval_accuracy_report.json` |
| 语音问答响应延迟合理，语音问答目标小于 5 秒 | 性能脚本覆盖文本对话、路线规划、大屏、KG 图谱、健康检查 | `orchestrator/scripts/latency_report.py`、`docs/latency_report.json` |
| 系统稳定，长时间无响应和崩溃需规避 | 启动指南固定 8010 后端端口；TTS 具备多级降级；Neo4j 不可用时可 JSON 兜底 | `STARTUP_GUIDE.md`、`orchestrator/app/services/kg_repo.py` |
| 可选复杂场景，如定位/GPS | 小程序侧已有位置管理模块，Web 侧采用路线打卡和地图展示作为演示替代 | `miniprogram-tourist/src/utils/locationManager.js`、`frontend-web/src/components/ParkMap.vue` |

## 4. 评分项抓手

| 评分项 | 分值 | 答辩时重点 |
|---|---:|---|
| 功能完整度 | 40 | 游客端、后台、大屏三端闭环；文本/语音/数字人/路线/反馈均可演示 |
| 技术与创新性 | 30 | RAG + KG 个性化路线、VRM 本地渲染口型同步、情感分析生成运营建议 |
| 行业实用与体验性 | 20 | 解决导游资源紧张、信息单向传播、个性化不足和管理盲区 |
| 文档质量 | 10 | 启动指南、设计文档、准确率报告、性能报告、提交清单齐全 |

## 5. 7 分钟演示视频脚本

1. 0:00-0:40 说明痛点：导游资源稀缺、录音讲解无法互动、游客个性化需求强、管理方缺少反馈数据。
2. 0:40-1:20 展示总体架构：游客端、Orchestrator、Dify/LLM、本地知识库、KG、后台和大屏。
3. 1:20-2:20 游客端路线推荐：选择兴趣和游览时长，生成个性化路线与讲解开场白。
4. 2:20-3:30 多模态问答：文本提问和语音提问各一次，展示数字人表情、动作、口型和 TTS 播报。
5. 3:30-4:20 途中交互：景点打卡、下一站提示、路线重规划或跳过景点。
6. 4:20-5:10 管理后台：知识库上传、数字人形象管理、游客反馈建议。
7. 5:10-5:50 数据大屏：服务人次、热门问答、景点热度、满意度趋势。
8. 5:50-6:40 测试证据：展示准确率报告和性能报告，说明 90% 准确率与稳定性验证。
9. 6:40-7:00 总结价值：提升游客体验、降低人工成本、辅助景区数字化运营。

## 6. 演示前检查

1. 后端固定监听 `http://127.0.0.1:8010`，前端入口为 `http://localhost:5173`。
2. 运行 `npm run build` 验证 `frontend-web`、`frontend-admin`、`frontend-dashboard` 构建通过。
3. 运行 `python -m scripts.eval_accuracy` 生成准确率报告。
4. 已启动真实服务时运行 `python -m scripts.latency_report --base-url http://127.0.0.1:8010`；无真实服务时可运行 `python -m scripts.latency_report --stub` 展示报告格式。
5. 录制前准备 3 个固定问题：历史知识、路线推荐、服务设施或拍照点。
