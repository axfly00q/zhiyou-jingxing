# 智游景行 PPT 整体框架与逐页内容

## 一、汇报主线

本项目不要讲成“一个 AI 聊天系统”，而要讲成：

> 智游景行是一套面向景区真实导览场景的 AI 数字人服务系统，覆盖游客交互、知识问答、个性化路线、数字人讲解、游客反馈分析、后台管理和数据大屏，形成“游客服务 + 景区运营”的闭环。

答辩时反复强调这条闭环：

游客提问 / 选择偏好 -> AI 数字人讲解 -> RAG 知识问答 -> KG 个性路线 -> 游客反馈 -> 后台分析 -> 景区优化。

## 二、PPT 建议页数

建议 14-16 页。时间紧就讲 12 页，时间宽就讲 16 页。

## 三、逐页内容

### 1. 封面

标题：

智游景行：景区导览 AI 数字人系统

副标题：

面向智慧景区的多模态交互、个性化路线推荐与运营反馈闭环

页面内容：

- 项目名称
- 团队名称 / 成员
- 指导老师
- 比赛名称

讲解重点：

一句话介绍：我们做的是景区 AI 数字人导游，不只是问答，而是游客端、后台和大屏一体化系统。

### 2. 项目背景与痛点

标题：

传统景区导览存在的核心问题

内容：

| 痛点 | 具体表现 | 项目对应解决方案 |
|---|---|---|
| 导游资源不足 | 旺季人工导游压力大，服务质量不稳定 | AI 数字人 7x24 小时服务 |
| 讲解体验单一 | 传统讲解器只能播放固定内容 | 支持文本、语音、互动问答 |
| 个性化不足 | 不同游客兴趣和时间不同，但路线推荐固定 | KG 个性化路线规划 |
| 反馈难沉淀 | 景区难知道游客真正不满意什么 | 情感分析与服务建议 |
| 管理缺数据 | 热门问题、景点热度、满意度不透明 | 数据大屏与后台分析 |

老师觉得好的点：

这个项目不是为了用 AI 而用 AI，而是从真实行业问题出发。

### 3. 项目目标

标题：

项目建设目标

内容：

- 构建可互动的 AI 数字人导游
- 支持景区知识问答与语音播报
- 根据游客偏好推荐游览路线
- 将游客反馈转化为运营建议
- 为管理方提供知识维护、数字人管理和数据分析能力

可以放一句定位：

从“单向讲解”升级为“可对话、可推荐、可反馈、可运营”的智慧导览系统。

### 4. 总体技术架构

推荐图片：

`docs/ppt_assets/image2_01_system_architecture.png`

标题：

系统总体架构

讲解顺序：

1. 用户交互层：游客端、小程序、Web，负责文本、语音、偏好和打卡。
2. Orchestrator 编排层：统一处理聊天、语音、路线、大屏和后台接口。
3. AI 与知识层：Dify/RAG、本地知识库、知识图谱、ASR/TTS、VRM 数字人。
4. 运营管理层：管理后台、知识库维护、数字人配置、数据大屏和服务建议。

老师觉得好的点：

系统层次清晰，不是简单调一个大模型接口，而是有完整工程架构。

### 5. 游客端核心体验

标题：

游客端：从路线推荐到数字人讲解

内容：

- 进入游客端
- 选择游览偏好：时间、兴趣、亲子、无障碍、赶时间
- 系统生成个性化路线
- 数字人进行景点讲解
- 游客可以继续提问、语音互动、景点打卡

页面建议：

左侧放游客端截图，右侧放流程：

偏好选择 -> 路线生成 -> 数字人讲解 -> 景点打卡 -> 继续问答

讲解重点：

这部分要让老师感觉产品“能用”，不是只停留在技术概念。

### 6. 多模态数字人交互链路

推荐图片：

`docs/ppt_assets/image2_02_multimodal_avatar_pipeline.png`

标题：

多模态数字人交互链路

讲解内容：

- 输入端：文字、语音、偏好、上下文
- AI 推理：ASR 转写、RAG 检索、LLM 生成、路线规划
- 行为映射：情绪标签、动作标签、口型同步、TTS 音频
- 输出端：VRM 数字人形象、表情、动作、语音讲解

老师觉得好的点：

数字人不是静态摆设，而是和语音、知识问答、动作表情联动。

### 7. RAG 景区知识问答

标题：

基于 RAG 的景区知识问答

推荐图片：

`docs/ppt_assets/image2_03_rag_kg_route_planning.png` 的上半部分

内容：

- 景区资料进入知识库
- 文档切分和向量索引
- 游客提问后检索相关知识片段
- LLM 基于检索内容生成回答
- 输出回答并保留引用来源

可以强调：

RAG 的价值是让回答“有依据、可追溯、少幻觉”，更适合景区历史文化类问答。

示例问题：

- 灵山大佛什么时候建成？
- 九龙灌浴有什么看点？
- 梵宫适合拍照吗？

### 8. KG 个性化路线规划

标题：

基于知识图谱的个性化路线推荐

推荐图片：

`docs/ppt_assets/image2_03_rag_kg_route_planning.png` 的下半部分，或 `docs/ppt_assets/04_kg_route_planning.svg`

讲解内容：

- 将景点抽象为图谱节点
- 将景点距离、游览顺序、主题关联抽象为图谱关系
- 根据游客偏好过滤和排序
- 输出可解释路线与讲解重点

可以写评分逻辑：

路线得分 = 兴趣匹配度 + 景点价值 - 距离成本 - 拥挤成本

老师觉得好的点：

路线推荐不是简单固定模板，而是结合偏好和景点关系进行规划。

### 9. 管理后台

标题：

管理后台：让系统可运营、可维护

内容：

- 知识库上传与维护
- 数字人模型、动作、声音配置
- 游客反馈与服务建议查看
- 后台权限和管理接口

页面建议：

放后台截图，旁边列功能。

讲解重点：

后台说明项目具备长期运营能力，不是一次性演示系统。

### 10. 数据大屏

标题：

数据大屏：景区运营状态可视化

内容：

- 今日导览人次
- 热门问题 Top
- 景点热度排行
- 满意度趋势
- 情感趋势与服务建议

老师觉得好的点：

大屏把游客行为转化成管理决策依据，体现行业实用价值。

### 11. 游客反馈到运营优化闭环

推荐图片：

`docs/ppt_assets/image2_04_operation_feedback_loop.png`

标题：

游客服务与景区运营闭环

讲解内容：

1. 游客通过问答、评价、抱怨产生交互数据。
2. 系统记录对话日志和行为数据。
3. 情感分析识别满意度和负面问题。
4. 后台生成服务建议。
5. 管理方优化知识库、路线策略和现场服务。
6. 游客获得更好的导览体验。

老师觉得好的点：

这页是项目高级感的关键：从“服务游客”上升到“辅助景区运营”。

### 12. 项目创新点

标题：

项目创新点

内容建议：

| 创新点 | 说明 |
|---|---|
| RAG + 景区知识库 | 用真实景区资料增强回答，降低大模型幻觉 |
| KG 个性化路线规划 | 根据游客偏好、景点关系和游览约束生成路线 |
| 多模态数字人交互 | 文字、语音、TTS、表情、动作、口型同步融合 |
| 游客反馈运营闭环 | 将对话和评价转化为后台服务建议 |
| 三端协同产品形态 | 游客端、管理后台、数据大屏共同构成完整系统 |

讲解重点：

不要只说“用了大模型”，要说“我们把大模型和景区业务流程结合起来”。

### 14. 测试与验证

标题：

测试与验证结果

内容：

- 功能测试：游客端、后台、大屏可演示
- 准确率测试：已有离线评测，整体约 94.12%
- 性能测试：接口延迟报告覆盖聊天、路线、大屏、图谱、健康检查
- 稳定性：TTS 降级、Neo4j 不可用时 JSON 兜底、启动指南固定端口

建议补强：

- RAG 事实问答专项准确率报告
- 语音端到端延迟报告
- 连续问答 / 简单并发稳定性报告

老师觉得好的点：

能拿出测试证据，比单纯口头说“效果不错”更有说服力。

### 15. 应用价值

标题：

应用价值与推广前景

内容：

| 对象 | 价值 |
|---|---|
| 游客 | 获得个性化、互动式、随时可用的导览服务 |
| 景区 | 降低导游压力，提高服务效率 |
| 管理方 | 掌握游客关注点、满意度和服务短板 |
| 平台 | 可扩展到多个景区，形成标准化智慧导览方案 |

可扩展方向：

- 拍照识景
- 多语言导览
- 实时客流感知
- 天气适配路线
- 家庭共享路线
- 离线基础导览

### 16. 总结

标题：

总结

推荐总结语：

智游景行围绕景区导览的真实需求，构建了一个集 AI 数字人、多模态交互、RAG 知识问答、KG 个性化路线、后台管理和数据大屏于一体的智慧导览系统。项目既能提升游客体验，也能帮助景区实现数据化运营，具备较强的落地价值和扩展空间。

最后一句：

我们的目标不是做一个会聊天的机器人，而是做一个真正能服务游客、辅助景区运营的 AI 数字人导览平台。

## 四、老师最容易认可的表达

### 1. 不要说

- 我们用了大模型。
- 我们做了一个聊天系统。
- 可以回答游客问题。

### 2. 要说

- 我们构建了景区导览服务闭环。
- RAG 让回答基于真实景区资料，减少幻觉。
- KG 让路线推荐从固定模板变成个性化规划。
- 数字人将知识问答、语音播报、动作表情统一成更自然的交互入口。
- 后台和大屏让游客反馈变成可执行的运营建议。

## 五、答辩演示建议

推荐演示顺序：

1. 打开游客端，展示数字人第一屏。
2. 选择游览偏好，生成路线。
3. 问一个景区知识问题。
4. 做一次语音提问和 TTS 播报。
5. 展示数字人表情、动作或口型。
6. 展示后台知识库或数字人管理。
7. 展示服务建议和数据大屏。
8. 最后展示测试报告和完成度矩阵。

固定演示问题：

- 灵山大佛什么时候建成？
- 九龙灌浴有什么看点？
- 帮我规划一条 2 小时的文化游路线。
- 景区里哪里适合拍照？
- 如果游客抱怨排队太久，系统如何安抚并记录？
