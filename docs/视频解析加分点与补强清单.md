# 视频解析加分点与补强清单

来源：B 站视频《2026中国软件杯赛题解析-A5-景区导览服务AI数字人》（BV1okLX6EEEw）关键帧与赛题截图整理。视频无公开字幕，以下按画面章节与赛题要求归纳。

## 1. 视频强调的评审视角

视频目录把赛题拆成 6 个部分：

1. 业务背景
2. 核心目标与价值
3. 功能需求与数据说明
4. 数字人相关要求
5. 核心技术指标
6. 提交材料与评分要点

这说明评审不只看“能不能聊天”，更看完整业务闭环、数字人效果、技术指标证据和材料表达。

## 2. 必须讲清楚的四个行业痛点

视频把传统景区导览痛点明确为：

| 痛点 | 答辩表达 | 项目对应能力 |
|---|---|---|
| 资源瓶颈 | 旺季专业导游不足，服务质量不稳定 | 7x24 小时 AI 数字人导游 |
| 体验单一 | 录音讲解固定，无法互动和个性化 | 文本/语音问答、路线推荐、景点打卡 |
| 信息单向 | 传统设备只播放内容，不能收集反馈 | 满意度评价、情感分析、热门问题统计 |
| 管理盲区 | 景区难量化导览质量和游客关注点 | 后台建议、数据大屏、景点热度分析 |

演示视频开头建议直接用这四点做问题陈述，再逐个展示系统如何解决。

## 3. 功能完整度的加分重点

### 游客端

视频强调游客端不是普通聊天框，而应包含：

| 评审关注点 | 当前状态 | 建议 |
|---|---|---|
| 数字人形象展示 | 已有 VRM 数字人、动作、口型 | 演示时必须放在第一屏，突出“数字人导游”而不是“问答页面” |
| 多模态交互界面 | 已有文本、语音、TTS、表情动作 | 演示至少做一次语音提问，展示播报、口型、表情联动 |
| 情感互动 | 已有情感标签与动作映射 | 增加一段“游客抱怨排队久”演示，展示安抚和后台记录 |
| 智能问答 | 已有 RAG/知识库 | 准备 3 个固定高命中问题，避免现场随机问答翻车 |
| 路线规划与讲解 | 已有偏好路线、打卡、重规划 | 演示“偏好选择 -> 生成路线 -> 到达景点 -> 下一站提示”闭环 |
| 创新探索 | 已有徽章、答题、分享卡 | PPT 里单独放“游戏化与分享传播”作为体验加分项 |

### 管理后台

视频单独列出后台需求，建议演示里必须给 40-50 秒：

| 评审关注点 | 当前状态 | 建议 |
|---|---|---|
| 知识库管理 | 已有知识上传/维护入口 | 演示上传或展示一份景区资料，说明可持续运营 |
| 数据可视化 | 已有大屏/分析接口 | 展示服务人次、热门问题、景点热度、满意度 |
| 数字人配置 | 已有形象管理页面 | 展示模型、动作、声音配置能力 |
| 运营闭环 | 已有情感分析和服务建议 | 强调“游客反馈 -> 后台建议 -> 管理优化” |

## 4. 数字人和 AI 技术指标

视频把数字人能力拆成三块：数字人引擎、对话大模型、本地知识库。

| 指标 | 当前状态 | 风险/缺口 | 补强建议 |
|---|---|---|---|
| 数字人引擎 | three-vrm 本地渲染，支持 VRM/VRMA | 需要证明自然度 | 录制一段数字人讲解视频，展示口型、表情、动作同步 |
| 对话大模型 | Dify/RAG + LLM 编排 | 如果评委强调“多模态大模型”，纯文本 LLM 说服力略弱 | 加一个“拍照识景/图片问答”规划或最小功能，作为多模态模型亮点 |
| 本地知识库 | `kb/tour_guide` + `kg/lingshan.json` | 需要证明知识来自景区资料 | PPT 中展示知识库来源、切片、RAG 流程和典型问答 |
| 准确率 | 自研模块评测 94% | 当前不是完整 RAG 事实问答准确率 | 增加 30-50 条景区事实问答黄金集，输出 RAG 准确率报告 |
| 语音响应 | 有 ASR/TTS 链路和降级 | 性能脚本主要测文本接口 | 增加语音问答端到端延迟记录，证明目标 <5 秒 |
| 稳定性 | 有启动指南、降级、健康检查 | 并发/长时间运行证据不足 | 增加 10-30 轮连续问答和并发压测截图/报告 |

## 5. 最值得补的加分项

按投入产出排序：

1. **补一份 RAG 事实问答准确率报告**
   - 为什么加分：视频明确提到知识问答准确率不低于 90%。
   - 做法：整理 30-50 条灵山景区事实问题，记录标准答案、系统答案、是否正确。
   - 交付：`docs/rag_accuracy_report.json` + PPT 一页“准确率 90%+”。

2. **补语音端到端延迟证明**
   - 为什么加分：技术指标里强调交互响应，语音问答延迟小于 5 秒。
   - 做法：准备 3 条短语音样例，记录 ASR、RAG、TTS、总耗时。
   - 交付：`docs/voice_latency_report.json` + 演示视频中展示一次真实语音。

3. **强化数字人自然度展示**
   - 为什么加分：数字人不是装饰，评委会看口型、表情、动作是否自然。
   - 做法：录制 20 秒数字人讲景点片段，展示欢迎、思考、讲解、安抚四类动作。
   - 交付：PPT 放短视频或 GIF，对应“数字人自然度”。

4. **突出后台运营闭环**
   - 为什么加分：视频把管理盲区作为痛点，后台是区别于普通游客聊天 demo 的核心。
   - 做法：演示游客抱怨 -> 情感分析 -> 后台服务建议/满意度趋势。
   - 交付：PPT 用流程图说明“游客侧数据反哺景区运营”。

5. **增加拍照识景作为多模态亮点**
   - 为什么加分：更贴合“多模态大模型”，也更像真实景区场景。
   - 最小版本：游客上传景点照片，系统识别候选景点并给讲解。
   - 可先写入 PPT “扩展能力”，若时间允许再做最小 demo。

## 6. 当前项目没有完全做到的地方

| 优先级 | 缺口 | 影响 | 建议处理 |
|---|---|---|---|
| P0 | RAG 事实问答准确率没有单独报告 | 可能被质疑“90% 准确率”证据不够直接 | 补黄金集评测 |
| P0 | 语音端到端延迟没有报告 | 技术指标证据不完整 | 补语音延迟报告或演示截图 |
| P1 | 数字人自然度缺少量化/专家评价 | 体验性评分可能吃亏 | 补自然度评价表 |
| P1 | 管理后台闭环在演示脚本中时长偏短 | 后台价值容易被忽略 | 演示必须展示后台建议和大屏 |
| P1 | 多模态大模型的“多模态”说服力可加强 | 目前更像文本 LLM + ASR/TTS 组合 | 增加图片识景或明确说明多模态链路 |
| P2 | 真实景区数据来源说明不够醒目 | 文档质量和实用性受影响 | PPT/文档增加数据来源页 |
| P2 | 并发稳定性证据不足 | 系统稳定性证明弱 | 补连续问答/并发压测小报告 |

## 7. 7 分钟演示建议改版

1. 0:00-0:35 痛点：资源瓶颈、体验单一、信息单向、管理盲区。
2. 0:35-1:05 方案：游客端 + AI 数字人 + 本地知识库 + 管理后台 + 数据大屏。
3. 1:05-2:00 个性化路线：选偏好、生成路线、地图/进度展示。
4. 2:00-3:10 多模态数字人：文本问答、语音问答、TTS、口型、表情动作。
5. 3:10-3:50 途中服务：打卡讲解、下一站提示、路线重规划。
6. 3:50-4:40 反馈闭环：提交评价或抱怨，后台看到情感/建议。
7. 4:40-5:30 后台能力：知识库管理、数字人配置、数据可视化。
8. 5:30-6:20 技术证据：RAG、KG、准确率、延迟、降级稳定性。
9. 6:20-7:00 创新总结：个性化、互动数字人、运营闭环、可扩展到拍照识景/多景区。
